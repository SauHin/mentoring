Discrete mathematics · 05

Inference dengan quantifier dan teknik pembuktian

Materi 02 membahas argumen untuk proposisi. Di sini argumennya memakai ∀ dan ∃. Bukti matematika adalah argumen valid yang disusun dari aturan-aturan ini.

Slide · Visualisasi: quantifier playground

TL;DR
  • Instantiation = turun dari quantifier ke satu elemen. Generalization = naik dari elemen ke quantifier.
  • "Semua A adalah B, c adalah A, jadi c adalah B" = universal modus ponens.
  • Empat teknik bukti: direct, contrapositive, contradiction, induction.
  • Contoh hanya membuktikan ∃. Untuk ∀, ambil elemen sembarang (arbitrary), lalu buktikan secara umum.

1. Kenapa butuh aturan baru

"Setiap mahasiswa SCE wajib mengambil discrete math. Jackson mahasiswa SCE. Jadi Jackson wajib mengambil discrete math." Argumen ini jelas benar, tapi tidak bisa dibuktikan dengan truth table. Ketiga kalimatnya hanya menjadi p, q, r yang tidak berhubungan.

Solusinya: turunkan ∀ ke Jackson dulu, baru pakai modus ponens.

1. ∀x, SCE(x) → DM(x)       premise
2. SCE(Jackson)             premise
3. SCE(Jackson) → DM(Jackson)   universal instantiation dari 1
4. DM(Jackson)              modus ponens dari 2 dan 3

2. Empat aturan quantifier

AturanBentukArtinya
Universal instantiation∀x P(x) ∴ P(c)Kalau berlaku untuk semua, berlaku untuk c mana pun
Universal generalizationP(c) untuk c sembarang ∴ ∀x P(x)Kalau terbukti untuk c tanpa memakai sifat khusus c, berlaku untuk semua
Existential instantiation∃x P(x) ∴ P(c) untuk suatu cBeri nama pada "yang ada itu". Nama c harus baru
Existential generalizationP(c) ∴ ∃x P(x)Satu contoh cukup untuk ∃ (witness)
Hati-hati dengan generalization"Sembarang" berarti c tidak dipilih secara khusus. Membuktikan P(2) lalu menyimpulkan ∀x P(x) itu salah. Contoh benar: "ambil x real sembarang. x² = x·x ≥ 0, jadi ∀x ∈ ℝ, x² ≥ 0".

Contoh dari kuliah

Tom dan Jerry. "Tidak ada kucing yang bisa menangkap Jerry. Tom kucing. Jadi Tom tidak bisa menangkap Jerry."

1. ∀x, Cat(x) → ~Catch(x)   premise
2. Cat(Tom)                 premise
3. Cat(Tom) → ~Catch(Tom)   universal instantiation dari 1
4. ~Catch(Tom)              modus ponens dari 2 dan 3

Sam dapat A. "Siapa pun yang nilainya > 80 dapat A. Ada mahasiswa yang nilainya > 80, dan Sam salah satunya."

1. ∀x, M(x) → A(x)          premise
2. ∃x, M(x)                 premise
3. M(Sam)                   existential instantiation (c = Sam)
4. M(Sam) → A(Sam)          universal instantiation dari 1
5. A(Sam)                   modus ponens dari 3 dan 4

Jual saham. "Kalau semua orang menjual saham, pasti ada yang menjual saham." Dari ∀x Sell(x) turunkan ke Sell(c) (universal instantiation), lalu naikkan ke ∃x Sell(x) (existential generalization). Ini berlaku asal domainnya tidak kosong.

Universal modus ponens dan tollens

Langkah instantiation + modus ponens begitu sering muncul, sehingga digabung menjadi satu aturan:

NamaBentukStatus
Universal modus ponens∀x, P(x) → Q(x); P(a) ∴ Q(a)Valid
Universal modus tollens∀x, P(x) → Q(x); ~Q(a) ∴ ~P(a)Valid
Converse error∀x, P(x) → Q(x); Q(a) ∴ P(a)Tidak valid
Inverse error∀x, P(x) → Q(x); ~P(a) ∴ ~Q(a)Tidak valid

Contoh converse error: "Semua kucing berbulu. Rex berbulu. Jadi Rex kucing." Padahal Rex bisa saja anjing.

3. Teknik pembuktian

Hampir semua teorema berbentuk ∀x, P(x) → Q(x). Polanya selalu sama: ambil x sembarang yang memenuhi P(x), lalu tunjukkan Q(x). Bedanya ada di cara menunjukkan Q(x).

Direct proof

Asumsikan P(x), lalu turunkan langkah demi langkah sampai Q(x).

Contoh (trik Euler): buktikan 0 + 1 + … + n = n(n + 1)/2. Tulis jumlahnya dua kali, maju dan mundur:

  S =   0   +   1   + … + (n−1) +   n
  S =   n   + (n−1) + … +   1   +   0
 2S =   n   +   n   + … +   n   +   n     (n + 1 suku)
 2S = n(n + 1)   →   S = n(n + 1)/2

Proof by contrapositive

Kadang P → Q sulit, tapi ~Q → ~P mudah. Keduanya ekuivalen (materi 01), jadi cukup buktikan yang mudah.

Contoh: "Untuk n bilangan bulat, kalau n² genap maka n genap." Contrapositive: kalau n ganjil maka n² ganjil.

n ganjil  →  n = 2k + 1
n² = 4k² + 4k + 1 = 2(2k² + 2k) + 1   →  ganjil  ∎

Proof by contradiction

Asumsikan pernyataannya salah, yaitu P benar dan Q salah. Turunkan sampai muncul kontradiksi C ∧ ~C (sesuatu yang benar dan salah sekaligus). Karena kontradiksi tidak mungkin, asumsinya pasti salah.

Contoh yang sama: misalkan n² genap tetapi n ganjil. Maka n = 2k + 1, jadi n² = 2(2k² + 2k) + 1 ganjil. Ini bertentangan dengan "n² genap". ∎

Kenapa valid? Truth table menunjukkan (~S → (C ∧ ~C)) ≡ S. Coba cek di visualisasi truth table.

Mathematical induction

Untuk statement ∀n ≥ 1, P(n). Dua langkah:

  1. Basis step: tunjukkan P(1) benar.
  2. Inductive step: asumsikan P(k) benar (inductive hypothesis), lalu tunjukkan P(k + 1) benar.

Kenapa valid? Seperti domino, atau naik tangga. P(1) benar, dan P(1) → P(2), jadi P(2) benar (modus ponens). Lalu P(2) → P(3), dan seterusnya. Secara formal: [P(1) ∧ ∀k (P(k) → P(k + 1))] → ∀n P(n).

Contoh: 1 + 2 + … + n = n(n + 1)/2.

Basis:     n = 1  →  1 = 1·2/2  ✓
Hipotesis: 1 + … + k = k(k + 1)/2
Langkah:   1 + … + k + (k + 1) = k(k + 1)/2 + (k + 1)
                               = (k + 1)(k + 2)/2         ✓ ini bentuk P(k + 1)
Trik menulis inductive stepTulis dulu P(k + 1) yang ingin dicapai di kertas. Lalu pecah sisi kirinya menjadi "bagian P(k)" + "suku baru", dan ganti bagian P(k) dengan hipotesis.

Kode bisa mengecek, tapi tidak membuktikan

Program di bawah mengecek rumus untuk n = 1 sampai 1000. Ini berguna untuk mencari counterexample, tapi tidak membuktikan ∀n. Bisa saja rumusnya gagal di n = 1001.

#include <stdio.h>

int main() {
    long long jumlah = 0;
    int n;
    for (n = 1; n <= 1000; n++) {
        jumlah += n;                                   /* jumlah = 1 + 2 + ... + n */
        if (jumlah != (long long)n * (n + 1) / 2) {
            printf("Counterexample: n = %d\n", n);
            return 0;
        }
    }
    printf("Cocok untuk n = 1..1000 (bukan bukti!)\n");
    return 0;
}

Struktur induksi mirip loop ini: basis = nilai awal, inductive step = setiap putaran mempertahankan sifatnya.

Kapan memakai teknik yang mana

TeknikCocok jika
DirectP memberi informasi yang bisa langsung diolah (rumus, definisi)
Contrapositive~Q lebih mudah diolah daripada P. Contoh: "n ganjil" memberi n = 2k + 1, sedangkan "n² genap" sulit diolah

5. Latihan

1. Tunjukkan bahwa ∀x, P(x) → Q(x) ekuivalen dengan contrapositive-nya.

Jawaban

Untuk setiap x, P(x) → Q(x) ≡ ~Q(x) → ~P(x) (logical equivalence). Kalau dua predicate bernilai sama untuk setiap x, maka ∀ dari keduanya juga bernilai sama.

2. Tunjukkan ~(∀x, P(x) → Q(x)) ≡ ∃x, P(x) ∧ ~Q(x).

Jawaban

~∀x (P → Q) ≡ ∃x ~(P → Q) ≡ ∃x (P ∧ ~Q). Langkah pertama memakai negasi quantifier, langkah kedua memakai ~(p → q) ≡ p ∧ ~q.

3. Premise: (1) untuk setiap bilangan x, kalau x > 1 maka x − 1 > 0. (2) Setiap bilangan di D lebih dari 1. Buktikan: untuk setiap x di D, x − 1 > 0.

Jawaban 
1. ∀x, x > 1 → x − 1 > 0     premise
2. ∀x ∈ D, x > 1             premise
3. c > 1, c ∈ D sembarang     universal instantiation dari 2
4. c > 1 → c − 1 > 0          universal instantiation dari 1
5. c − 1 > 0                  modus ponens dari 3 dan 4
6. ∀x ∈ D, x − 1 > 0          universal generalization (c sembarang)

4. q bilangan real positif. Buktikan atau bantah: kalau q irrational, maka √q irrational.

Jawaban

Benar, buktikan dengan contrapositive: kalau √q rational, maka q rational. Misalkan √q = a/b dengan a, b bulat dan b ≠ 0. Maka q = a²/b², yang juga pecahan bulat, jadi rational. ∎

5. Buktikan dengan induksi: jumlah n bilangan ganjil positif pertama = n². (1 + 3 + … + (2n − 1) = n²)

Jawaban 
Basis:     n = 1  →  1 = 1²  ✓
Hipotesis: 1 + 3 + … + (2k − 1) = k²
Langkah:   1 + 3 + … + (2k − 1) + (2k + 1) = k² + 2k + 1 = (k + 1)²  ✓

6. Buktikan dengan induksi: n³ − n habis dibagi 3 untuk setiap n bulat positif.

Jawaban 
Basis:     n = 1  →  1 − 1 = 0, habis dibagi 3  ✓
Hipotesis: k³ − k = 3m untuk suatu bilangan bulat m
Langkah:   (k + 1)³ − (k + 1) = k³ + 3k² + 3k + 1 − k − 1
                             = (k³ − k) + 3(k² + k)
                             = 3m + 3(k² + k) = 3(m + k² + k)  ✓

7. Mana yang valid? (a) Semua programmer suka kopi. Ani tidak suka kopi. Jadi Ani bukan programmer. (b) Semua programmer suka kopi. Budi suka kopi. Jadi Budi programmer.

Jawaban

(a) Valid: universal modus tollens. (b) Tidak valid: converse error.
