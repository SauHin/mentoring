Notes 1️⃣ · IPO chart

IPO chart memisahkan data yang masuk, cara mengolahnya, dan hasil yang keluar

IPO chart adalah tabel tiga kolom untuk satu module. Contoh: Print Order Calculator (BW 500, Color 1,500 per halaman, binding +5,000).

  • Input hanya data dari luar. total bukan input, karena baru ada setelah dihitung.
  • Display ditulis di Output, bukan di Processing.

Notes 1️⃣ · Hierarchy chart

Hierarchy chart menunjukkan module mana memanggil module mana, bukan urutan langkah

Hierarchy chart (structure chart): main paling atas, module yang dipanggil di bawah pemanggilnya.

  • Garis polos tanpa panah, tanpa nomor urutan, tanpa decision.
  • Satu kotak = satu IPO chart. Isi kolomnya untuk setiap module.
  • Dipanggil dari dua tempat: gambar kotaknya dua kali.

Notes 2️⃣ · Pseudocode

Pseudocode memakai sedikit kata kunci, dengan satu aksi per baris

Pseudocode adalah langkah program dalam bahasa Inggris sederhana. Kata kuncinya dari buku Gaddis, buku acuan dosen.

Kata kunciFungsi
Declare Integer pagesmembuat variabel dan tipenya

Set total = pages * 500mengisi variabel
Display "Total: ", totalmenampilkan output
If … Then … Else … End Ifdecision

For i = 1 To 5 … End Forloop dengan counter
Module, Call, Function, Returnmodule dan function
  • == untuk membandingkan, = hanya di Set.
  • Indentasi 3 spasi di dalam blok, dan setiap If ditutup End If.
  • Bukan kode C: tanpa printf, scanf, atau titik koma.

Notes 2️⃣ · Pseudocode

Validasi input paling awal, lalu semua perhitungan ditaruh di cabang Then

Bagian inti pseudocode Print Order Calculator, setelah Declare dan Input. Trace di kanan memakai input Color, 10 halaman, binding Yes.

If (printType == "BW" OR printType == "Color") AND pages > 0 Then
   If printType == "Color" Then
      Set pricePerPage = 1500
   Else
      Set pricePerPage = 500
   End If
   Set total = pages * pricePerPage
   If binding == "Yes" Then
      Set total = total + 5000
   End If
   Display "Total: IDR ", total
Else
   Display "Error: choose BW or Color and enter pages > 0"
End If

Notes 2️⃣ · Pseudocode untuk GUI

Soal ber-GUI: satu event handler per tombol, input dari komponen, output ke label

Event handler adalah module yang jalan saat tombol diklik. Di Gaddis namanya namaTombol_Click.

Module clearButton_Click()
   Set bikeTypeDropdown.Text = "City Bike"
   Set durationTextBox.Text = ""
   Set totalLabel.Text = ""
End Module
  • Input: durationTextBox.Text, bukan Input.
  • Output: Set totalLabel.Text = fee, bukan Display.
  • Error di GUI: tampilkan di label lalu selesai. Pengguna memperbaiki dan klik lagi, jadi tidak perlu loop.

Notes 3️⃣ · Flowchart

Setiap jenis langkah punya simbol sendiri, dan pasangannya ada di pseudocode

Flowchart adalah gambar langkah program: simbol untuk jenis langkah, panah untuk urutan.

Notes 3️⃣ · Flowchart

Tiga struktur dasar: urut, bercabang lalu bertemu lagi, dan loop yang kembali ke decision

Semua flowchart di soal adalah gabungan tiga struktur ini.

Notes 3️⃣ · Flowchart

Flowchart adalah pseudocode yang digambar, dan cabang error tetap berakhir di End yang sama

Print Order Calculator. Connector A menyambung kolom kiri ke kolom kanan.

Notes 3️⃣ · Flowchart untuk GUI

Soal ber-GUI: satu flowchart per tombol, dengan tombol yang diklik di terminal atas

Contoh tombol Clear dari Latihan 1. Tombol Calculate Fee punya flowchart sendiri.

  • Input: "Get … from the form", karena data diambil dari komponen GUI.
  • Output: sebut labelnya, misalnya "Display fee in totalLabel".
  • Error: tampilkan di label, lalu ke End.

Notes 4️⃣ · DFD

DFD hanya punya empat simbol, dan semuanya diberi nama

Data flow diagram (DFD) menunjukkan siapa mengirim data masuk, siapa menerima data keluar, dan data apa yang disimpan. Notasi dosen: Gane & Sarson.

  • Tidak ada Start, decision, atau loop. DFD menunjukkan ke mana data bergerak, bukan urutan langkah.

Notes 4️⃣ · Aturan DFD

Data hanya berpindah lewat process, dan setiap process punya input dan output

Slide dosen menyebutnya law of conservation of data. Garis merah putus-putus = salah.

  • Setiap data flow diberi nama data yang dibawanya, misalnya "Loan receipt", bukan "Send".

Notes 4️⃣ · Context diagram

Context diagram: seluruh sistem satu process bernomor 0, dengan semua entity dan flow

Contoh Online Library Loan System. Data store belum digambar, karena masih dianggap bagian dari process 0.

  • Cek: setiap kalimat soal tentang data dari atau ke pihak luar menjadi satu flow di sini.

Notes 4️⃣ · Level 0

Level 0 menggabungkan satu fragment per use case, lalu menambahkan data store

DFD fragment = satu process beserta entity, data store, dan flow-nya. Entity dan store yang sama digambar sekali.

Notes 4️⃣ · Level 1 dan balancing

Level 1 memecah satu process, dan flow ke luar harus sama dengan induknya

Balancing: flow yang masuk dan keluar dari process 1 di Level 0 muncul semua di Level 1. Flow internal boleh ditambah.

  • Nomor: 1.1, 1.2, 1.3 untuk process 1.
  • Tidak boleh menghapus flow atau menambah flow baru ke entity.
  • Berhenti saat process bisa dijelaskan dalam satu kalimat. Idealnya 3 sampai 7 subprocess.

Notes 4️⃣ · DFD vs flowchart

DFD menjawab ke mana data mengalir, flowchart menjawab bagaimana logika berjalan

Notes 5️⃣ · Kanvas latihan

Coba sendiri: soal di kiri, kanvas di kanan, lalu tekan Cek aturan

Ringkasan: tandai soal, susun IPO, lalu gambar sesuai aturan alatnya

  • Strategi (0️⃣): enter/select = input, calculate = process, if = decision, display = output.
  • IPO dan hierarchy (1️⃣): tiga kolom per module; kotak main di atas, tanpa urutan.
  • Pseudocode (2️⃣): satu aksi per baris, == untuk membandingkan, validasi paling awal.
  • Flowchart (3️⃣): satu Start dan satu End, decision selalu Yes/No, soal GUI berarti satu flowchart per tombol.
  • DFD (4️⃣): data hanya lewat process, context = process 0, setiap level balanced.

Soal latihan: kerjakan dulu, jawabannya di slide berikutnya

  1. Bike Rental Fee Calculator (GUI). City Bike: IDR 15,000 jam pertama, IDR 5,000 per jam tambahan. E-Bike: IDR 25,000 dan IDR 10,000. Lebih dari 5 jam: diskon 10%. Durasi harus bilangan bulat positif. Tombol Calculate Fee dan Clear. Buat IPO chart, pseudocode, dan flowchart untuk kedua tombol.
  2. Online Clinic Appointment System. Patient mengirim appointment request. Sistem mengecek jadwal dokter, meminta pembayaran ke Payment Gateway, lalu mengirim konfirmasi setelah pembayaran terverifikasi. Doctor menerima daftar janji harian dan menandai selesai. Administrator mengelola jadwal dan menerima laporan bulanan. Buat context diagram, Level 0, dan Level 1 untuk process Book Appointment.

Soal lengkap berbahasa Inggris dan kanvasnya: Latihan 1 · Latihan 2
