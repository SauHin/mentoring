Notes 1️⃣ · IPO chart

IPO chart: komponen dan cara mengisi

IPO chart adalah tabel tiga kolom yang mencatat input, processing, dan output dari satu program atau module.

KolomIsinyaKata di soal
Inputdata yang dimasukkan penggunaenter, select, choose, type
Processinglangkah yang mengolah input: pengecekan, harga, rumuscheck, calculate, costs, adds
Outputhasil yang ditampilkan, termasuk pesan errordisplay, show
  1. Input: cari kata kerja pengguna, lalu tulis datanya sebagai kata benda (weight, service).
  2. Output: cari kata display atau show, lalu tulis apa yang ditampilkan.
  3. Processing: tulis semua langkah di antaranya secara berurutan: cek input dulu, baru hitung. Aturan yang bergantung pada pilihan ditulis sebagai If … Else.

Notes 1️⃣ · IPO chart

Contoh IPO chart: soal 1

Kuis meminta flowchart, tapi IPO chart dikerjakan dulu supaya isi flowchart sudah lengkap.

InputCek (processing)ProcessingOutput

InputProcessingOutput
  • service (Wash Only / Wash and Iron)
  • weight (kg)
  • express (Yes / No)
  • Check that service and express are filled and weight > 0
  • If service = Wash Only, pricePerKg = 8000. Else, pricePerKg = 12000
  • If weight < 1, billable = 1 (minimum 1 kg). Else, billable = weight
  • total = billable × pricePerKg
  • If express = Yes, total = total + 5000
  • Error message (if the input is invalid)
  • Order summary: service, weight, express, total

Notes 1️⃣ · Hierarchy chart

Hierarchy chart

Module adalah sekelompok langkah yang diberi nama dan dikerjakan bersama, misalnya calcAverage. Hierarchy chart menunjukkan module apa saja di program dan siapa memanggil siapa.

  • Kotak = satu module. main selalu paling atas.
  • Garis = memanggil. Pemanggil di atas, module yang dipanggil di bawahnya.
  • Tidak ada panah, urutan langkah, atau decision. Itu tugas pseudocode dan flowchart.

Notes 1️⃣ · Hierarchy chart

Module yang dipanggil dari dua tempat

Misalnya showSummary juga memanggil getPricePerKg untuk mencetak harga per kg.

  • Boleh: kotak getPricePerKg digambar di bawah setiap module yang memanggilnya, jadi muncul dua kali.
  • Module-nya tetap satu. Di pseudocode, getPricePerKg hanya ditulis sekali.
  • Dipanggil dua kali oleh module yang sama: cukup satu kotak.

Notes 2️⃣ · Pseudocode

Pseudocode

Pseudocode adalah langkah program yang ditulis dengan bahasa Inggris sederhana dan kata kunci tetap. Kata kuncinya dari buku Gaddis, buku acuan dosen.

Declare Real weight, total
Display "Weight (kg)?"
Input weight
Set total = weight * 8000
Display "Total: IDR ", total
  • Satu baris satu perintah, diawali kata kunci: Declare, Display, Input, Set.
  • Bukan kode C: tanpa printf, scanf, kurung kurawal, atau titik koma.
  • Contoh di kiri: membaca berat cucian, lalu menampilkan biaya Wash Only.

Notes 2️⃣ · Pseudocode

If-Then-Else dan operator

If memilih satu dari dua jalan. Setiap If ditutup dengan End If.

If weight < 1 Then
   Set billable = 1
Else
   Set billable = weight
End If
OperatorArti
== !=sama dengan, tidak sama dengan
< > <= >=lebih kecil, lebih besar, dan seterusnya
ANDbenar kalau kedua syarat benar
ORbenar kalau salah satu syarat benar
NOTkebalikan
  • == untuk membandingkan, = hanya untuk mengisi di Set. Else boleh tidak ada kalau tidak perlu.

Notes 2️⃣ · Pseudocode

Pseudocode soal 1

Soal 1: Wash Only 8,000/kg, Wash and Iron 12,000/kg, express +5,000, minimal 1 kg, cek input dulu.

Declare String service, express
Declare Real weight, pricePerKg
Declare Real billable, total

Display "Service?"
Input service
Display "Weight (kg)?"
Input weight
Display "Express (Yes/No)?"
Input express

If service != "" AND express != "" AND weight > 0 Then
   If service == "Wash Only" Then
      Set pricePerKg = 8000
   Else
      Set pricePerKg = 12000
   End If
   If weight < 1 Then
      Set billable = 1
   Else
      Set billable = weight
   End If
   Set total = billable * pricePerKg
   If express == "Yes" Then
      Set total = total + 5000
   End If
   Display service, weight, express
   Display "Total: IDR ", total
Else
   Display "Error: complete the data"
End If

Notes 2️⃣ · Pseudocode untuk GUI

Pseudocode soal 2: satu module per tombol

Event handler adalah module yang jalan saat tombol diklik. Di Gaddis namanya namaTombol_Click.

Module calculateButton_Click()
   Declare String vehicle = vehicleDropdown.Text
   Declare String durationText = durationTextBox.Text
   Declare Integer hours
   Declare Real first, extra, fee

   If isInteger(durationText) AND stringToInteger(durationText) > 0 Then
      Set hours = stringToInteger(durationText)
      If vehicle == "Motorcycle" Then
         Set first = 2000
         Set extra = 1000
      Else
         Set first = 5000
         Set extra = 3000
      End If
      Set fee = first + (hours - 1) * extra
      Set feeLabel.Text = fee
   Else
      Set feeLabel.Text = "Error: invalid duration"
   End If
End Module
  • Input dibaca dari komponen: durationTextBox.Text.
  • Output ditulis ke label: Set feeLabel.Text = fee.
  • Jam tambahan = hours - 1, karena jam pertama sudah dibayar first. Car 3 jam: 5000 + 2 × 3000 = 11000.
Module clearButton_Click()
   Set vehicleDropdown.Text = "Car"
   Set durationTextBox.Text = ""
   Set feeLabel.Text = ""
End Module

Notes 4️⃣ · DFD

DFD dan empat komponennya

Data flow diagram (DFD) menunjukkan siapa mengirim data, siapa menerimanya, dan data apa yang disimpan. Contoh di tabel dari sistem katering (soal 3).

SimbolKomponenContoh di sistem katering
ent a 0 0 Customer
External entity: orang, organisasi, atau sistem lain di luar sistem. Namanya kata benda.Customer: pelanggan yang memesan makanan. Ia mengirim pesanan dan menerima konfirmasi, tapi bukan bagian dari sistem.
dproc a 0 0 [3] Place Order
Process: kegiatan yang mengolah data. Bernomor, namanya kata kerja + objek.3 Place Order: sistem mencatat (place) pesanan (order): cek ketersediaan menu, hitung total, simpan pesanan.
store a 0 0 [D3] Orders
Data store: tempat data disimpan. ID-nya D1, D2, …D3 Orders: semua pesanan yang tersimpan di sistem.
pt a 0 0 pt b 130 0 a > b : Order details
Data flow: data yang bergerak. Selalu diberi nama data.Order details: menu, jumlah, dan alamat yang dikirim Customer ke process 3.

Notes 4️⃣ · Aturan DFD

Aturan DFD

Data hanya boleh berpindah lewat process, dan setiap process punya input dan output.

✗ Tidak boleh: entity langsung ke data store

ent m 0 0 Administrator store d 260 0 =140x40 [D2] Menu m > d : Menu data !

Data berpindah tanpa process.

✓ Benar: lewat process

ent m 0 0 Administrator dproc p 250 0 [1] Manage Menu store d 500 0 =130x40 [D2] Menu m > p : Menu data p > d : Menu record

Process yang menyimpan data ke data store.

✗ Tidak boleh: black hole

ent m 0 0 Customer dproc p 250 0 [3] Place Order ! m > p : Order details

Process hanya menerima data, tidak ada output.

✗ Tidak boleh: miracle

dproc p 0 0 [5] Generate Report ! ent l 250 0 Administrator p > l : Order report

Process mengeluarkan data tanpa input.

  • Setiap data flow diberi nama data yang dibawanya, misalnya "Order report", bukan "Send".

Notes 4️⃣ · Level 0

Level 0: satu fragment per process

DFD fragment adalah satu process beserta entity, data store, dan flow-nya. Ini fragment process 4 Process Payment.

  • Flow ke entity diambil dari context diagram.
  • Flow ke data store ditambah sekarang: process menyimpan atau membaca data.
  • Buat fragment untuk process 1 sampai 7, lalu gabungkan. Entity dan store yang sama digambar sekali.

Notes 4️⃣ · Level 0

Level 0 soal 3

Gabungan tujuh fragment. Semua flow dari context diagram ada di sini, dan setiap process punya tugas sendiri.

Notes 4️⃣ · Level 1

Level 1: process 3 Place Order

Process 3 dipecah mengikuti urutan kalimat soal: cek ketersediaan menu, hitung total, lalu simpan pesanan.

  • Nomor: 3.1, 3.2, 3.3.
  • Flow internal antar subprocess boleh ditambah (Available items, Order with total).
  • Berhenti memecah saat process bisa dijelaskan dalam satu kalimat. Idealnya 3 sampai 7 subprocess.

Notes 4️⃣ · Balancing

Balancing: cek Level 1 dengan Level 0

Balancing: semua flow process 3 di Level 0 harus muncul lagi di Level 1, tidak boleh hilang atau bertambah.

Flow process 3 di Level 0Di Level 1
Customer → Order details3.1 ✓
D2 → Menu availability3.1 ✓
Customer data → D13.3 ✓
New order → D33.3 ✓
  • Tidak boleh menambah flow baru ke entity di Level 1. Kalau perlu, tambahkan juga di Level 0 dan context diagram.

Notes 5️⃣ · Kanvas latihan

Coba di kanvas latihan

Ringkasan

  • IPO chart: input dari kata enter/select, output dari display/show, processing di antaranya. Cek input dulu.
  • Hierarchy chart: main di atas, module yang dipanggil di bawah pemanggilnya, tanpa urutan.
  • Pseudocode: Declare dulu, lalu Input, Set, Display, dan If … End If. Bandingkan dengan ==.
  • Flowchart: satu Start dan satu End, decision selalu Yes/No, soal GUI = satu flowchart per tombol.
  • DFD: context (process 0), lalu Level 0 dari fragment, lalu Level 1 yang balanced. Data hanya lewat process.

Soal latihan

Kerjakan dulu, jawabannya di slide berikutnya.

  1. Bike Rental Fee Calculator (GUI). City Bike: IDR 15,000 jam pertama, IDR 5,000 per jam tambahan. E-Bike: IDR 25,000 dan IDR 10,000. Lebih dari 5 jam: diskon 10%. Durasi harus bilangan bulat positif. Tombol Calculate Fee dan Clear. Buat IPO chart, pseudocode, dan flowchart untuk kedua tombol.
  2. Online Clinic Appointment System. Patient mengirim appointment request. Sistem mengecek jadwal dokter, meminta pembayaran ke Payment Gateway, lalu mengirim konfirmasi setelah pembayaran terverifikasi. Doctor menerima daftar janji harian dan menandai selesai. Administrator mengelola jadwal dan menerima laporan bulanan. Buat context diagram, Level 0, dan Level 1 untuk process Process Payment.
