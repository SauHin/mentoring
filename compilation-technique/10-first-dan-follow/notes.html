Predictive parsing, FIRST, dan FOLLOW

Parser top-down yang efisien memilih produksi hanya dengan melihat satu token, tanpa mencoba-coba. Untuk tahu token mana cocok dengan produksi mana, kita butuh dua set: FIRST dan FOLLOW. Target: kamu bisa menghitung FIRST dan FOLLOW setiap variabel tanpa melompati aturan, termasuk saat ada ε.

Recursive descent mencoba produksi satu per satu dan mundur (backtracking) kalau gagal

top-down parsing dan leftmost derivation (materi 07) predictive parser tanpa backtracking (2️⃣)

Mencari jalan di labirin: coba belok kiri, kalau buntu kembali ke persimpangan, lalu coba belok kanan.

di labirin kamu bisa menandai jalan yang sudah dicoba. Parser dengan backtracking bisa mengulang pekerjaan yang sama berkali-kali, jadi lambat.

Backtracking adalah kembali ke pilihan produksi terakhir dan mencoba alternatif lain, karena pilihan sebelumnya gagal. Recursive descent (parser top-down dengan satu fungsi rekursif per variabel, materi 07 dan 09) memakai cara ini sambil membangun parse tree dari atas dengan leftmost derivation.

Contoh slide: S → aBc, B → bc | b, input abc.

LangkahYang dicobaHasil
1S → aBc, cocokkan acocok
2B → bc (alternatif pertama), cocokkan b, ccocok, input habis
3kembali ke S, cocokkan c terakhirinput sudah habis, gagal. Backtrack ke B.
4B → b (alternatif kedua), cocokkan bcocok
5kembali ke S, cocokkan ccocok, input habis. Berhasil.

Cara ini umum dan bisa dipakai untuk banyak grammar, tapi tidak efisien, jadi jarang dipakai.

Backtracking = coba, gagal, mundur, coba alternatif lain. Benar, tapi lambat.

Soal latihan: Grammar yang sama, input ab. Apa yang terjadi?

S → aBc: a cocok. B → bc: b cocok, tapi c tidak ada, gagal. Backtrack, B → b: b cocok. S butuh c, input habis, gagal. B tidak punya alternatif lagi, jadi ab ditolak.

Predictive parser memilih produksi hanya dengan melihat token sekarang, jadi tidak perlu backtracking

backtracking (1️⃣), lookahead (materi 08) procedure per variabel (3️⃣), parser LL(1) (materi 11)

Petugas loket melihat jenis tiket di tanganmu dan langsung menunjuk antrean yang benar.

petugas bisa bertanya kalau ragu. Predictive parser tidak bisa: kalau dua produksi cocok dengan token yang sama, grammar itu tidak bisa dipakai.

Predictive parser adalah parser top-down yang memilih alternatif dari A → α₁ | … | αₙ hanya dengan melihat token input sekarang (lookahead, materi 08). Contoh slide:

stmt → if …  |  while …  |  begin …  |  for …

Kalau token sekarang if, pasti alternatif pertama. Tidak ada tebakan, jadi tidak ada backtracking. Supaya ini bisa, grammar biasanya disiapkan dulu:

  • Eliminasi left recursion (materi 09): kalau tidak, parser memanggil dirinya terus.
  • Left factoring (materi 08): kalau dua alternatif punya awalan sama, satu token tidak cukup.
  • Belum ada jaminan 100%: grammar yang benar-benar bisa disebut LL(1) grammar, dan cara mengeceknya ada di materi 11.

Predictive = satu token cukup untuk memilih produksi. Keduanya butuh FIRST dan FOLLOW.

Soal latihan: Bisakah predictive parser memakai S → ab | ac?

Tidak. Kedua alternatif diawali a, jadi token a tidak cukup untuk memilih. Left factoring dulu: S → aS', S' → b | c.

Recursive predictive parsing: satu procedure untuk setiap variabel, dan kasusnya dipilih dari token sekarang

predictive parser (2️⃣), fungsi dan switch di C ε-production (4️⃣)

Resep yang memanggil resep lain: "buat sausnya (lihat halaman 12)".

resep tidak perlu memilih. Procedure harus memilih kasus berdasarkan token sekarang.

Recursive predictive parsing adalah recursive descent tanpa backtracking: setiap variabel menjadi satu procedure, dan procedure itu memilih alternatif dari token sekarang. Contoh slide, A → aBb | bAB, ditulis dengan pseudo-code mirip C:

void A() {
    switch (token) {
        case 'a': match('a'); B(); match('b'); break;   // A → aBb
        case 'b': match('b'); A(); B(); break;          // A → bAB
        default:  error();
    }
}
  • Isi tiap case: ruas kanan produksi dibaca dari kiri ke kanan. Terminal menjadi match, variabel menjadi panggilan procedure-nya.
  • match(t): cek bahwa token sekarang sama dengan t, lalu maju ke token berikutnya. Kalau beda, error.
  • Label case: token yang mengawali alternatif itu.

Terminal = match, variabel = panggil procedure-nya, label case = token awal alternatif.

Soal latihan (slide dosen): Tulis procedure untuk A → aBb (satu-satunya produksi A). 
void A() {
    match('a');
    B();
    match('b');
}

Hanya ada satu alternatif, jadi tidak perlu switch. Kalau token pertama bukan a, match sendiri yang memberi error.

ε-production dipilih kalau token sekarang bisa muncul tepat setelah variabel itu

procedure per variabel (3️⃣) FIRST (5️⃣) dan FOLLOW (7️⃣)

Ruang tunggu yang boleh dilewati: kalau namamu tidak dipanggil di sini, kamu langsung lanjut ke ruangan berikutnya.

di dunia nyata siapa pun boleh lewat. Di parser, hanya token yang memang bisa datang berikutnya yang boleh lewat. Token lain berarti error.

Contoh slide: A → aBe | cBd | C, B → bB | ε, C → f.

void A() {
    switch (token) {
        case 'a': match('a'); B(); match('e'); break;
        case 'c': match('c'); B(); match('d'); break;
        case 'f': C(); break;              // f = terminal pertama dari C
        default:  error();
    }
}
void B() {
    switch (token) {
        case 'b': match('b'); B(); break;
        case 'e': case 'd': break;         // B → ε: e dan d bisa muncul setelah B
        default:  error();
    }
}
void C() { match('f'); }
  • Case f di A: alternatif C diawali variabel, jadi labelnya adalah terminal pertama yang bisa dihasilkan C. Set ini disebut FIRST (5️⃣).
  • Case e, d di B: B → ε tidak membaca apa pun, jadi labelnya adalah token yang bisa muncul tepat setelah B. Di A → aBe dan A → cBd, setelah B selalu ada e atau d. Set ini disebut FOLLOW (7️⃣).

Slide juga menyebut cara lain: pakai ε kalau semua alternatif lain gagal. Cara itu jalan, tapi error baru ketahuan belakangan. Cara yang benar menurut slide: pakai ε hanya kalau token ada di FOLLOW, bukan sembarang token.

Label case untuk A → α = FIRST(α). Label case untuk A → ε = FOLLOW(A).

Soal latihan: Di procedure B() di atas, apa yang terjadi kalau token sekarang d? Kalau f?

d: masuk case e, d, jadi B tidak melakukan apa-apa (B → ε) dan kembali ke A, yang lalu menjalankan match('d'). f: masuk default, error, karena f tidak pernah muncul tepat setelah B.

FIRST(α) berisi terminal yang bisa muncul paling depan di string hasil α

label case (4️⃣) FIRST dengan ε (6️⃣), tabel LL(1) (materi 11)

Huruf depan semua nama di satu kelas: cukup lihat daftar absen, tidak perlu kenal orangnya.

nama di absen sudah jadi. Variabel harus diturunkan dulu, dan kadang hasilnya kosong (ε). Hasil kosong itu dicatat juga.

FIRST(α) adalah set terminal yang bisa muncul sebagai simbol pertama dari string yang diturunkan dari α. Kalau α bisa menjadi ε, maka ε juga masuk FIRST(α).

FIRST = lihat simbol paling depan. Kalau variabel, pakai FIRST variabel itu.

Soal latihan: Hitung FIRST untuk A → aBe | cBd | C, B → bB | ε, C → f.

FIRST(C) = {f}. FIRST(B) = {b, ε}. FIRST(A) = {a, c, f}: a dan c dari terminal di depan, f dari FIRST(C). Bandingkan dengan label case di 4️⃣.

Kalau simbol paling depan bisa menjadi ε, FIRST lanjut ke simbol berikutnya

FIRST dasar (5️⃣), nullable di syntax tree RE (materi 04) FOLLOW aturan 2 (7️⃣), yang memakai FIRST dari deretan simbol

Foto barisan: kalau orang paling depan jongkok sampai tidak terlihat, yang terlihat paling depan adalah orang kedua.

orang yang jongkok tetap ada di foto. Variabel yang menjadi ε benar-benar hilang dari string.

Variabel yang bisa menurunkan ε disebut nullable, sama seperti nullable di materi 04. Untuk X → Y₁Y₂…Yₙ (aturan 2 di slide):

  1. Mulai dari Y₁: FIRST(Y₁) tanpa ε masuk FIRST(X).
  2. Kalau Y₁ nullable: lanjut, FIRST(Y₂) tanpa ε juga masuk. Begitu seterusnya, dan berhenti di simbol pertama yang tidak nullable.
  3. Kalau semua Yᵢ nullable: ε masuk FIRST(X).
S → ABc      A → a | ε      B → b | ε

FIRST(S): FIRST(A) tanpa ε = {a}    A nullable, lanjut ke B
          FIRST(B) tanpa ε = {b}    B nullable, lanjut ke c
          c terminal       = {c}    berhenti
FIRST(S) = {a, b, c}

Cara yang sama dipakai untuk FIRST dari deretan simbol, misalnya FIRST(Bc) = {b, c}. Deretan ini nanti dipakai di FOLLOW.

ε di FIRST(A) tidak otomatis masuk FIRST(S). Di contoh atas, FIRST(S) tidak memuat ε, karena c tidak bisa hilang.

Lanjut ke simbol berikutnya selama simbol sekarang nullable. ε masuk hanya kalau semuanya nullable.

Soal latihan: S → AB, A → a | ε, B → b | ε. Berapa FIRST(S)?

FIRST(A) tanpa ε = {a}. A nullable, jadi lanjut: FIRST(B) tanpa ε = {b}. B juga nullable, dan tidak ada simbol lagi, jadi ε masuk. FIRST(S) = {a, b, ε}.

FOLLOW(A) berisi terminal yang bisa muncul tepat setelah A: mulai dari $ dan simbol di sebelah kanan A

label case untuk ε (4️⃣), FIRST deretan simbol (6️⃣) aturan 3 (8️⃣), tabel LL(1) (materi 11)

Siapa saja yang pernah duduk tepat di sebelah kananmu, di semua kelas yang kamu ikuti.

di kelas, kalau kamu duduk di ujung, kursi sebelahmu kosong. Di FOLLOW, kalau A ada di paling akhir, yang "duduk" setelahnya diambil dari variabel induknya (8️⃣).

FOLLOW(A) adalah set terminal yang bisa muncul tepat setelah variabel A, di string mana pun yang diturunkan dari start symbol. Tanda akhir input $ masuk FOLLOW(A) kalau A bisa berada di paling akhir.

AturanIsi
1$ masuk FOLLOW(S), dengan S = start symbol
2Untuk produksi A → αBβ: FIRST(β) tanpa ε masuk FOLLOW(B)
  • Cari B di ruas kanan semua produksi, bukan di ruas kiri. Setiap kemunculan B diperiksa.
  • Cara cepat (slide): kalau tepat setelah B ada terminal, terminal itu langsung masuk FOLLOW(B).

Contoh grammar ekspresi: E start symbol, jadi $ masuk. Di F → (E), tepat setelah E ada ). Jadi FOLLOW(E) = {), $}.

FOLLOW tidak pernah memuat ε. Saat memakai FIRST(β), buang ε-nya.

FOLLOW(B) = lihat apa yang ada di kanan B. Start symbol selalu mendapat $.

Soal latihan: S → ABc, A → a | ε, B → b | ε. Hitung FOLLOW(S), FOLLOW(A), FOLLOW(B).

FOLLOW(S) = {$} (aturan 1, S tidak muncul di ruas kanan). FOLLOW(A): setelah A ada Bc, dan FIRST(Bc) = {b, c}, jadi {b, c}. FOLLOW(B): tepat setelah B ada c, jadi {c}.

Kalau B ada di paling kanan, atau sisanya bisa ε, FOLLOW variabel kiri ikut masuk ke FOLLOW(B)

aturan 1 dan 2 (7️⃣) tabel LL(1) (materi 11)

Kamu duduk paling kanan di barisan kelompokmu. Orang yang duduk setelahmu adalah siapa pun yang duduk setelah kelompokmu.

batas kelompok di kelas terlihat jelas. Di grammar, "kelompok" adalah variabel kiri A, dan yang duduk setelahnya adalah FOLLOW(A).

AturanBentuk produksiIsi
3aA → αB (B paling kanan)semua FOLLOW(A) masuk FOLLOW(B)
3bA → αBβ, dan β nullablesemua FOLLOW(A) masuk FOLLOW(B)

Alasannya: B adalah bagian paling akhir dari A, jadi token apa pun yang mengikuti A juga mengikuti B. Arahnya dari A ke B: FOLLOW(A) masuk FOLLOW(B), bukan sebaliknya.

Kalau FOLLOW(A) belum selesai dihitung, pakai isinya sekarang dan cek lagi nanti. Ulangi semua aturan sampai tidak ada set yang bertambah.

Contoh slide: FOLLOW grammar ekspresi

E' → +TE' juga membuat E' paling kanan di produksinya sendiri. Itu memasukkan FOLLOW(E') ke dirinya sendiri, jadi tidak menambah apa-apa. Hal yang sama untuk T'.

Contoh slide: S → iCtSE | a, E → eS | ε, C → b (perlu dicek ulang)
  1. FOLLOW(S): $ (aturan 1). Di S → iCtSE, setelah S ada E: FIRST(E) tanpa ε = {e}. Di E → eS, S paling kanan, jadi FOLLOW(E) masuk, tapi FOLLOW(E) belum dihitung. Sementara: {e, $}.
  2. FOLLOW(E): di S → iCtSE, E paling kanan, jadi FOLLOW(S) = {e, $} masuk. Hasil: {e, $}.
  3. FOLLOW(C): tepat setelah C ada t. Hasil: {t}.
  4. Cek ulang FOLLOW(S): FOLLOW(E) sekarang {e, $}, dan isinya sudah ada di FOLLOW(S). Tidak ada yang bertambah, jadi selesai.

B paling kanan, atau sisanya nullable: FOLLOW(kiri) masuk FOLLOW(B). Ulangi sampai tidak berubah.

FIRST: lihat ke depan. FOLLOW: lihat ke kanan B, lalu ke variabel induknya.

Soal latihan: Temanmu menulis FOLLOW(E') = {), $, ε}. Apa yang salah?

ε tidak pernah masuk FOLLOW. FOLLOW berisi token yang bisa muncul setelah E', dan ε bukan token. Yang benar: FOLLOW(E') = {), $}.
