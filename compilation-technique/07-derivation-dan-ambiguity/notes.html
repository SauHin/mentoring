Derivation, parse tree, dan ambiguity

Parser mengecek apakah urutan token bisa diturunkan dari grammar. Bukti penurunannya ditulis sebagai derivation (LMD atau RMD) atau digambar sebagai parse tree. Target: kamu bisa menulis LMD, RMD, dan parse tree, lalu membuktikan grammar ambiguous atau tidak.

Lexer mengecek setiap kata, parser mengecek susunan kata-kata itu

lexer dan token (materi 01), CFG (materi 06) derivation (2️⃣) dan strategi parsing (7️⃣)

Guru bahasa mengecek susunan kalimat setelah ejaan setiap kata dicek.

guru bisa memaklumi kalimat yang agak salah. Parser menolak susunan yang tidak ada di grammar.

Parser (syntax analyzer) menerima token dari lexer, mengecek apakah urutannya mengikuti grammar, membangun parse tree (atau AST), dan melaporkan syntax error.

source program → lexer → token → parser → parse tree / AST → semantic analysis

if ( x > 0 )     token valid, susunan valid
if ( > x 0 )     token valid, susunan tidak valid: syntax error

Parser meminta token satu per satu ke lexer, membaca dari kiri ke kanan. Grammar bahasa pemrograman ditulis sebagai CFG, biasanya dalam notasi BNF.

Lexer: kata valid atau tidak. Parser: susunan valid atau tidak.

Soal latihan: Pada x = 5 + ;, lexer atau parser yang melaporkan error?

Parser. Setiap token (x, =, 5, +, ;) valid, tapi setelah + grammar mengharapkan operand, bukan ;.

LMD selalu mengganti variabel paling kiri, RMD selalu paling kanan

derivation (materi 06) parse tree (3️⃣), top-down dan bottom-up (7️⃣)

Mengisi formulir dari kolom paling kiri, atau dari kolom paling kanan: hasil akhirnya formulir yang sama.

urutan mengisi formulir bebas. Di LMD dan RMD, aturan pemilihannya harus konsisten di setiap baris.

Kalau sentential form punya lebih dari satu variabel, kamu harus memilih mana yang diganti. Leftmost derivation (LMD) selalu memilih yang paling kiri, rightmost derivation (RMD) yang paling kanan.

S → AB    A → a    B → b

LMD: S ⇒ AB ⇒ aB ⇒ ab      (A diganti dulu)
RMD: S ⇒ AB ⇒ Ab ⇒ ab      (B diganti dulu)
LMDRMD

LMD: kiri dulu. RMD: kanan dulu. Keduanya dari S ke string.

E ⇒ E*E ⇒ (E)*E ⇒ (E+E)*E ⇒ (a+E)*E ⇒ (a+b)*E ⇒ (a+b)*c

Parse tree mencatat produksi yang dipakai, tanpa urutan penggantian

LMD dan RMD (2️⃣) AST (4️⃣) dan ambiguity (5️⃣)

Silsilah keluarga: siapa anak dari siapa, tanpa mencatat siapa lahir duluan.

silsilah bisa punya banyak cabang. Anak sebuah node parse tree persis ruas kanan produksi yang dipakai.

Parse tree: root = start symbol, node dalam = variabel, anak-anaknya = ruas kanan produksi yang dipakai, leaf = terminal (atau ε). Membaca leaf dari kiri ke kanan menghasilkan string-nya. Karena urutan penggantian tidak dicatat, LMD dan RMD menghasilkan tree yang sama.

id * id ada di bawah satu T, jadi perkalian dikelompokkan lebih dulu. Grammar ini menegakkan prioritas * di atas +.

Di visualisasi, jalankan LMD lalu RMD untuk string yang sama. Tree yang terbentuk sama.

Parse tree = produksi yang dipakai. Satu tree bisa ditulis sebagai satu LMD dan satu RMD.

Soal latihan (slide dosen): Grammar E → E + T | T, T → T * F | F, F → ( E ) | id, string id + id * id. Buat LMD, RMD, dan parse tree. Apakah grammar ini menegakkan prioritas perkalian? 
LMD: E ⇒ E+T ⇒ T+T ⇒ F+T ⇒ id+T ⇒ id+T*F ⇒ id+F*F ⇒ id+id*F ⇒ id+id*id
RMD: E ⇒ E+T ⇒ E+T*F ⇒ E+T*id ⇒ E+F*id ⇒ E+id*id ⇒ T+id*id ⇒ F+id*id ⇒ id+id*id

Parse tree-nya adalah gambar di atas. Ya, prioritas ditegakkan: * hanya bisa dihasilkan dari T, dan T berada di bawah E. Jadi id * id selalu menjadi satu subtree di bawah +. Langkah pertama keduanya sama (E → E + T), karena operator dengan prioritas terendah harus di puncak tree.

ringkasan bisa kehilangan isi penting. AST hanya membuang detail grammar, arti program tetap utuh.

Soal latihan: Jelaskan bentuk AST untuk (a+b)*c.

* di root, anak kiri + (dengan anak a dan b), anak kanan c. Kurung hilang, karena strukturnya sudah menunjukkan bahwa a+b dikelompokkan dulu.

Grammar ambiguous kalau ada satu string dengan dua parse tree

parse tree (3️⃣) menghilangkan ambiguity (6️⃣)

"Saya melihat orang dengan teropong": siapa yang memegang teropong?

manusia bisa bertanya balik. Compiler harus memilih satu arti tanpa bertanya.

Grammar ambiguous kalau ada string di L(G) dengan lebih dari satu parse tree (atau lebih dari satu LMD). Satu contoh string sudah cukup sebagai bukti. Dengan E → E + E | E * E | id:

Ambiguity berbahaya karena kedua tree memberi hasil hitung berbeda, padahal compiler harus memberi satu arti.

Di visualisasi, pilih mode cek ambiguity. Kalau ada dua tree, keduanya bisa dibandingkan.

Dua parse tree (atau dua LMD) untuk satu string = ambiguous.

Soal latihan: Tunjukkan bahwa S → aS | Sa | a ambiguous.

String aa punya dua LMD: S ⇒ aS ⇒ aa dan S ⇒ Sa ⇒ aa. Dua LMD berbeda = dua parse tree, jadi ambiguous.

Ambiguity pada ekspresi dihilangkan dengan satu variabel untuk setiap tingkat prioritas

ambiguous grammar (5️⃣), prioritas operator di C left recursion (materi 09)

Struktur organisasi: staf (*) di bawah manajer (+). Pekerjaan staf selesai dulu sebelum dilaporkan ke manajer.

organisasi bisa dirombak. Grammar ini memaksa pengelompokan yang sama untuk setiap ekspresi.

Tidak ada algoritma umum yang bisa menghilangkan ambiguity. Untuk ekspresi, triknya:

E → E + T | T       (prioritas terendah)
T → T * F | F
F → ( E ) | id      (paling kuat)
  • Prioritas: * hanya muncul di level T, yang berada di bawah E. Jadi perkalian dikelompokkan dulu.
  • Associativity: rekursi di kiri (E → E + T) membuat a + b + c dibaca (a + b) + c, yaitu left associative.
  • Kurung: ( E ) kembali ke level teratas, jadi bisa mengubah prioritas.
Dari slide: language yang semua grammar-nya ambiguous

Inherently ambiguous: context-free language yang semua grammar-nya ambiguous. Contoh dari slide: L = {aⁿbⁿcᵐdᵐ | n, m ≥ 1} ∪ {aⁿbᵐcᵐdⁿ | n, m ≥ 1}, dengan grammar S → AB | C, A → aAb | ab, B → cBd | cd, C → aCd | aDd, D → bDc | bc. String aabbccdd masuk ke kedua bagian, jadi selalu punya dua tree. Menentukan apakah sebuah grammar ambiguous pun tidak bisa diputuskan oleh algoritma.

Satu level per prioritas, rekursi kiri untuk left associative, kurung kembali ke level teratas.

Soal latihan: Buat RMD untuk id * ( id + id ) dengan grammar di atas. 
E ⇒ T ⇒ T*F ⇒ T*(E) ⇒ T*(E+T) ⇒ T*(E+F) ⇒ T*(E+id) ⇒ T*(T+id)
  ⇒ T*(F+id) ⇒ T*(id+id) ⇒ F*(id+id) ⇒ id*(id+id)

Top-down membangun tree dari root, bottom-up dari leaf

LMD dan RMD (2️⃣) left factoring dan left recursion (materi 08, 09)

Menyusun puzzle dari gambar besarnya dulu (top-down), atau dari potongan kecil yang cocok (bottom-up).

puzzle boleh disusun campuran. Satu parser memakai satu arah saja.

Top-down parsing mulai dari start symbol dan menebak produksi. Keduanya membaca input dari kiri ke kanan, satu token per langkah. Parser yang efisien hanya bisa dibuat untuk sebagian CFG: LL untuk top-down, LR untuk bottom-up.

Mulai daristart symboltoken input

Aksimemprediksi produksi, expandshift dan reduce

Top-down = LMD, dari root. Bottom-up = kebalikan RMD, dari leaf.

Soal latihan: Parser LL memakai derivation yang mana? Parser LR?

LL (top-down) memakai LMD. LR (bottom-up) membangun kebalikan RMD: langkah terakhir RMD dikerjakan pertama.

Error recovery: empat cara parser melanjutkan setelah syntax error

tugas parser (1️⃣) pesan error yang kamu lihat saat compile program C

Salah jalan: putar balik ke persimpangan terdekat, atau perbaiki belokan terakhir saja.

di jalan kamu tahu tujuanmu. Parser hanya bisa menebak maksud programmer.

Saat input melanggar grammar, parser tidak langsung berhenti, supaya error lain tetap ditemukan. Strategi paling sederhana adalah panic mode:

StrategiCara kerjaKelebihanKekurangan
Panic modeBuang token sampai bertemu synchronizing token (;, })Sederhana, tidak pernah infinite loopBisa melewati banyak input
Phrase levelPerbaikan lokal: sisipkan, hapus, atau ganti tokenKesalahan kecil diperbaiki tanpa banyak input hilangSulit memilih perbaikan yang tepat
Error productionsTambahkan produksi untuk kesalahan yang umumPesan error informatifKesalahan harus diperkirakan dulu
Global correctionCari jumlah perubahan minimum supaya input validOptimal secara teoriTerlalu mahal untuk compiler nyata

Panic mode membuang token sampai titik aman. Strategi lain mencoba memperbaiki input.

Soal latihan: Kenapa panic mode tidak pernah infinite loop?

Setiap kali dipakai, panic mode membuang minimal satu token. Input terus berkurang, jadi parser pasti mencapai synchronizing token atau akhir input.

Kesalahan yang sering muncul: salah memilih variabel dan salah membaca definisi ambiguous

semua section sebelumnya mengecek derivation-mu sendiri

Dua rute ke rumah yang sama tidak berarti ada dua rumah.

di peta, dua rute memang wajar. Di grammar, LMD dan RMD untuk satu tree juga wajar. Yang membuat ambiguous adalah dua tree.

Cek setiap baris derivation: variabel mana yang diganti, dan apakah sesuai aturan LMD atau RMD.

KesalahanKenapa salahPerbaikan
LMD yang mengganti variabel di tengahLMD harus selalu variabel paling kiriCek setiap baris
RMD ditulis dari string ke SRMD tetap derivation: dari S ke stringMulai dari S, ganti variabel paling kanan
"LMD dan RMD berbeda, jadi ambiguous"LMD dan RMD dari tree yang sama selalu berbeda urutanAmbiguous = 2 parse tree (atau 2 LMD) untuk satu string
"Satu string punya 1 tree, jadi unambiguous"String lain bisa saja punya 2 treeUnambiguous harus berlaku untuk semua string

Bandingkan LMD dengan LMD (atau tree dengan tree), bukan LMD dengan RMD.

Soal latihan: Temanmu bilang E → E + T | T, T → T * F | F, F → ( E ) | id ambiguous karena LMD dan RMD untuk id + id * id berbeda. Benarkah?

Tidak. LMD dan RMD itu menghasilkan parse tree yang sama, jadi bukan bukti ambiguity. Untuk membuktikan ambiguous, dibutuhkan dua LMD berbeda (dua tree) untuk satu string, dan grammar ini tidak punya.
