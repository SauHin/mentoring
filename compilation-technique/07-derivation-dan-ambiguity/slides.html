Derivation, parse tree, dan ambiguity

Compilation technique · soal "buat leftmost derivation, rightmost derivation, dan parse tree", serta "apakah grammar ini ambiguous?".

Tugas parser

Lexer hanya mengecek apakah setiap kata valid. Parser (syntax analyzer) mengecek apakah urutan token mengikuti grammar, lalu membangun parse tree.

source program → lexer → token → parser → parse tree / AST → semantic analysis
  • if ( > x 0 ): setiap token valid, jadi lexer tidak protes. Urutannya tidak cocok dengan grammar if ( expr ), jadi parser melaporkan syntax error.
  • Parser meminta token satu per satu ke lexer ("get next token"), membaca dari kiri ke kanan.
  • Grammar bahasa pemrograman ditulis sebagai CFG, biasanya dalam notasi BNF.

Leftmost dan rightmost derivation

Kalau sentential form punya lebih dari satu variabel, kita harus memilih variabel mana yang diganti dulu. Dua aturan pemilihan yang baku:

  • Leftmost derivation (LMD): selalu ganti variabel paling kiri. Dipakai parser top-down.
  • Rightmost derivation (RMD): selalu ganti variabel paling kanan. Parser bottom-up membangun kebalikan RMD.
  • Keduanya dimulai dari start symbol dan berakhir di string yang sama.
S → AB    A → a    B → b

LMD: S ⇒ AB ⇒ aB ⇒ ab
RMD: S ⇒ AB ⇒ Ab ⇒ ab

Oranye = variabel yang diganti di langkah berikutnya.

Latihan dosen: id + id * id

Grammar: E → E + T | T, T → T * F | F, F → ( E ) | id. Setiap baris mengganti tepat satu variabel (oranye).

LMD
E ⇒ E + T
  ⇒ T + T
  ⇒ F + T
  ⇒ id + T
  ⇒ id + T * F
  ⇒ id + F * F
  ⇒ id + id * F
  ⇒ id + id * id
RMD
E ⇒ E + T
  ⇒ E + T * F
  ⇒ E + T * id
  ⇒ E + F * id
  ⇒ E + id * id
  ⇒ T + id * id
  ⇒ F + id * id
  ⇒ id + id * id

Langkah pertama keduanya sama: E → E + T, karena operator dengan prioritas paling rendah (+) harus berada di puncak tree.

Parse tree

Parse tree menunjukkan produksi mana yang dipakai untuk setiap variabel, tanpa urutan penggantian. Karena itu LMD dan RMD di slide sebelumnya menghasilkan tree yang sama.

  • Root = start symbol, leaf = terminal, node dalam = variabel. Anak-anak sebuah node = ruas kanan produksi yang dipakai.
  • Baca leaf dari kiri ke kanan: id + id * id.
  • id * id ada di bawah satu T, jadi perkalian dihitung lebih dulu. Grammar ini menegakkan prioritas * di atas +.

Parse tree dan abstract syntax tree (AST)

Parse tree mencatat bagaimana string di-parse. Tahap compiler berikutnya cukup tahu apa artinya, jadi biasanya memakai AST yang lebih ringkas.

Menghilangkan ambiguity: satu level per prioritas

Tidak ada algoritma umum untuk menghilangkan ambiguity. Untuk ekspresi, triknya: buat satu variabel untuk setiap tingkat prioritas.

E → E + T | T       (prioritas terendah)
T → T * F | F
F → ( E ) | id      (paling kuat)
  • + hanya bisa muncul di level E, * hanya di level T. Karena T berada di bawah E, perkalian selalu dikelompokkan lebih dulu.
  • E → E + T (rekursi di kiri) membuat a + b + c dibaca (a + b) + c: left associative.
  • Kurung ( E ) kembali ke level teratas, jadi bisa mengubah prioritas.

Top-down dan bottom-up parsing

Kedua strategi membaca input dari kiri ke kanan, tetapi membangun tree dari arah yang berlawanan.

Top-downBottom-up
ArahRoot ke leaf: mulai dari start symbolLeaf ke root: mulai dari token
DerivationLeftmost derivationKebalikan rightmost derivation
AksiMenebak produksi, lalu expandShift dan reduce
Contoh parserRecursive descent, LLLR, SLR, LALR
Syarat grammarTidak boleh left recursive, perlu left factoringBisa menangani left recursion

Kesalahan yang sering muncul

Kesalahan derivation biasanya karena salah memilih variabel. Kesalahan ambiguity biasanya karena salah membaca definisinya.

KesalahanKenapa salahPerbaikan
LMD yang mengganti variabel di tengahLMD harus selalu variabel paling kiriCek setiap baris: variabel paling kiri yang diganti
RMD ditulis dari string ke SRMD tetap derivation: dari S ke stringMulai dari S, ganti variabel paling kanan
"LMD dan RMD berbeda, jadi ambiguous"LMD dan RMD dari tree yang sama selalu berbeda urutanAmbiguous = 2 parse tree (atau 2 LMD) untuk satu string
"Satu string punya 1 tree, jadi unambiguous"String lain bisa saja punya 2 treeUnambiguous harus berlaku untuk semua string

Ringkasan

  • Parser mengecek urutan token terhadap grammar dan membangun parse tree.
  • LMD mengganti variabel paling kiri, RMD paling kanan. Keduanya dari S ke string, dan menghasilkan parse tree yang sama.
  • Grammar ambiguous kalau satu string punya dua parse tree. Untuk ekspresi, hilangkan dengan satu variabel per tingkat prioritas.
  • Top-down memakai LMD, bottom-up membangun kebalikan RMD.
