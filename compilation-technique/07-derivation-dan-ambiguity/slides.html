Derivation, parse tree, dan ambiguity

Compilation technique · materi 07 · prasyarat: CFG (materi 06)

Target: kamu bisa menulis LMD, RMD, dan parse tree, lalu membuktikan grammar ambiguous atau tidak.

Label di atas setiap judul (misalnya "Notes 3️⃣") menunjuk section notes yang membahas hal yang sama secara lengkap.

Notes 1️⃣ · Parser

Lexer mengecek setiap kata, parser mengecek susunan kata-kata itu

Parser (syntax analyzer) mengecek apakah urutan token mengikuti grammar, lalu membangun parse tree.

source program → lexer → token → parser → parse tree / AST → semantic analysis
  • if ( > x 0 ): setiap token valid, tapi urutannya tidak cocok dengan if ( expr ), jadi parser melaporkan syntax error.
  • Parser meminta token satu per satu ke lexer, membaca dari kiri ke kanan.
  • Grammar bahasa pemrograman ditulis sebagai CFG, biasanya dalam notasi BNF.

Notes 2️⃣ · LMD dan RMD

LMD selalu mengganti variabel paling kiri, RMD selalu paling kanan

Kalau ada lebih dari satu variabel, leftmost derivation (LMD) dan rightmost derivation (RMD) adalah dua aturan baku memilih variabel.

  • LMD: ganti variabel paling kiri. Dipakai parser top-down.
  • RMD: ganti variabel paling kanan. Parser bottom-up membangun kebalikannya.
  • Keduanya dimulai dari S dan berakhir di string yang sama.
S → AB    A → a    B → b

LMD: S ⇒ AB ⇒ aB ⇒ ab
RMD: S ⇒ AB ⇒ Ab ⇒ ab

Oranye = variabel yang diganti di langkah berikutnya.

Notes 3️⃣ · Parse tree

Latihan dosen id + id * id: LMD dan RMD sama-sama mulai dengan E → E + T

Grammar: E → E + T | T, T → T * F | F, F → ( E ) | id. Setiap baris mengganti tepat satu variabel (oranye).

LMD
E ⇒ E + T
  ⇒ T + T
  ⇒ F + T
  ⇒ id + T
  ⇒ id + T * F
  ⇒ id + F * F
  ⇒ id + id * F
  ⇒ id + id * id
RMD
E ⇒ E + T
  ⇒ E + T * F
  ⇒ E + T * id
  ⇒ E + F * id
  ⇒ E + id * id
  ⇒ T + id * id
  ⇒ F + id * id
  ⇒ id + id * id

Langkah pertama keduanya sama, karena operator dengan prioritas paling rendah (+) harus berada di puncak tree.

Notes 3️⃣ · Parse tree

LMD dan RMD di slide sebelumnya menghasilkan parse tree yang sama

Parse tree mencatat produksi yang dipakai untuk setiap variabel, tanpa urutan penggantian.

  • Struktur: root = start symbol, leaf = terminal, anak sebuah node = ruas kanan produksinya.
  • Membaca: leaf dari kiri ke kanan menghasilkan id + id * id.
  • Prioritas: id * id ada di bawah satu T, jadi perkalian dikelompokkan dulu.

Notes 5️⃣ · Ambiguity

Grammar ambiguous kalau ada satu string dengan dua parse tree

Grammar ambiguous punya string dengan lebih dari satu tree (atau LMD). Contoh E → E + E | E * E | id:

Compiler harus memberi satu arti, jadi grammar seperti ini harus ditulis ulang.

Notes 6️⃣ · Menghilangkan ambiguity

Ambiguity pada ekspresi dihilangkan dengan satu variabel untuk setiap tingkat prioritas

Tidak ada algoritma umum untuk menghilangkan ambiguity. Untuk ekspresi, triknya satu level per prioritas.

E → E + T | T       (prioritas terendah)
T → T * F | F
F → ( E ) | id      (paling kuat)
  • Prioritas: * hanya muncul di level T, di bawah E, jadi dikelompokkan dulu.
  • Left associative: E → E + T membuat a + b + c dibaca (a + b) + c.
  • Kurung: ( E ) kembali ke level teratas.

Notes 7️⃣ · Top-down dan bottom-up

Top-down membangun tree dari root memakai LMD, bottom-up dari leaf memakai kebalikan RMD

Keduanya membaca input dari kiri ke kanan. Top-down parsing menebak produksi dari start symbol.

Top-downBottom-up
ArahRoot ke leafLeaf ke root
DerivationLeftmostKebalikan rightmost
AksiMenebak produksi, lalu expandShift dan reduce
Contoh parserRecursive descent, LLLR, SLR, LALR
Syarat grammarTidak boleh left recursive, perlu left factoringBisa menangani left recursion

Syarat grammar top-down dibahas di materi 08 (left factoring) dan 09 (left recursion).

Notes 8️⃣ · Error recovery

Setelah syntax error, parser melanjutkan supaya error lain tetap ditemukan

Strategi paling sederhana adalah panic mode. Tiga strategi lain mencoba memperbaiki input.

StrategiCara kerjaKelebihan dan kekurangan
Panic modeBuang token sampai ; atau }Sederhana, tapi bisa melewati banyak input
Phrase levelSisipkan, hapus, atau ganti tokenSedikit input hilang, tapi sulit memilih perbaikan
Error productionsProduksi tambahan untuk kesalahan umumPesan informatif, tapi kesalahan harus diperkirakan
Global correctionPerubahan minimum supaya validOptimal, tapi terlalu mahal

Notes 9️⃣ · Kesalahan umum

Kesalahan paling sering: salah memilih variabel dan salah membaca definisi ambiguous

Setiap baris menyebut penyebab salahnya dan cara memperbaikinya.

KesalahanKenapa salahPerbaikan
LMD mengganti variabel di tengahLMD harus variabel paling kiriCek setiap baris
RMD ditulis dari string ke SRMD tetap dari S ke stringMulai dari S, ganti variabel paling kanan
"LMD dan RMD berbeda, jadi ambiguous"LMD dan RMD dari tree yang sama selalu beda urutanAmbiguous = 2 tree (atau 2 LMD)
"Satu string punya 1 tree, jadi unambiguous"String lain bisa punya 2 treeHarus berlaku untuk semua string

Ringkasan

Derivation dan parse tree adalah bukti bahwa string bisa diturunkan dari grammar.

  • LMD mengganti variabel paling kiri, RMD paling kanan. Keduanya menghasilkan parse tree yang sama.
  • Ambiguous: satu string punya dua parse tree. Untuk ekspresi, hilangkan dengan satu variabel per prioritas.
  • Top-down memakai LMD, bottom-up membangun kebalikan RMD.
  • Error recovery: panic mode, phrase level, error productions, global correction.

Soal

Kerjakan dulu, lalu cek jawabannya di slide berikutnya.

  1. Dengan E → E+E | E*E | (E) | a | b | c | d, buat LMD untuk (a+b)*c.
  2. Tunjukkan bahwa S → aS | Sa | a ambiguous.
  3. Dengan E → E + T | T, T → T * F | F, F → ( E ) | id, buat RMD untuk id * ( id + id ).
