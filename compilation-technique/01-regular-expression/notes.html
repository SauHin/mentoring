Regular expression

Regular expression (RE) adalah cara menulis sebuah language (himpunan string) dengan rumus pendek. Lexer memakai RE untuk mengenali token, dan semua soal automata berikutnya dimulai dari sebuah RE.

Slide · Visualisasi: cek RE kamu

TL;DR
  • Tiga operator: r* (nol kali atau lebih), rs (concatenation), r|s atau r+s (union). Prioritas: star, lalu concatenation, lalu union.
  • Membaca RE: tulis string terpendek yang dihasilkan, lalu cari polanya.
  • Menulis RE: pola diawali X(0|1)*, diakhiri (0|1)*X, memuat (0|1)*X(0|1)*, posisi ke-k dari kanan, dan union untuk "atau". Untuk "dan", union semua urutan.
  • Selalu uji jawabanmu dengan ε, string terpendek, dan string yang hampir benar.

1. RE di dalam compiler

Tahap pertama compiler adalah lexical analyzer (scanner). Lexer membaca source code karakter demi karakter, lalu mengelompokkannya menjadi potongan bermakna. Parser meminta token satu per satu ke lexer ("get next token"), jadi lexer tidak membuat daftar token sekaligus.

Source:  position = initial + rate * 60
Token:   <id,1> <=> <id,2> <+> <id,3> <*> <number,60>
IstilahArtiContoh
LexemePotongan teks asli di source codeposition, =, 60
TokenPasangan <nama token, attribute>. Satu token mewakili banyak lexeme, jadi attribute menyimpan informasi lexeme yang mana.<id,1>: attribute = posisi di symbol table
PatternAturan bentuk lexeme untuk satu token, biasanya ditulis sebagai REid → letter (letter | digit)*

Contoh kelas token dari slide:

Lexical error dan input bufferingLexer hampir tidak bisa mendeteksi kesalahan program. Pada fi ( a == f(x) ), lexer tidak tahu apakah fi salah ketik untuk if atau nama fungsi, jadi fi tetap menjadi id. Lexer juga sering harus membaca satu karakter lebih jauh: setelah <, ia harus melihat karakter berikutnya untuk tahu apakah lexeme-nya < atau <=. Karena itu lexer memakai dua pointer (lexemeBegin dan forward) di atas buffer input.

3. Operasi pada language

RE adalah singkatan untuk operasi-operasi ini. Misalkan L = {0, 1, 00, 01, 10} dan M = {10, 11}.

OperasiDefinisiContoh
Concatenation LM{xy | x ∈ L, y ∈ M}: satu string dari L lalu satu dari MLM = {010, 011, 110, 111, 0010, 0011, 0110, 0111, 1010, 1011}
Union L ∪ M{x | x ∈ L atau x ∈ M}L ∪ M = {0, 1, 00, 01, 10, 11}
Kleene closure L*L⁰ ∪ L¹ ∪ L² ∪ …: gabungan nol string atau lebih dari L{1}* = {ε, 1, 11, 111, …}
Positive closure L⁺L¹ ∪ L² ∪ …: minimal satu{1}⁺ = {1, 11, 111, …}

Contoh lain dari slide: (1100)* = {ε, 1100, 11001100, …} dan (00+11)* = {ε, 00, 11, 0000, 0011, 1100, 1111, …}.

4. Operator RE dan prioritasnya

Definisi RE bersifat rekursif: ∅, ε, dan setiap simbol a adalah RE. Kalau r dan s adalah RE, maka r|s (atau r+s), rs, dan r* juga RE.

  • Prioritas: star paling kuat, lalu concatenation, lalu union. Jadi ab*|c = (a(b*))|c.
  • r? = r|ε (boleh ada, boleh tidak).
  • r⁺ = rr*. Slide menulis baa(b|a)+ untuk "baa diikuti minimal satu simbol". Karena + juga dipakai untuk union, lebih aman menulis baa(a|b)(a|b)*.

Sifat aljabar yang berguna untuk menyederhanakan RE (r, s, t adalah RE):

r|s = s|r                 (r|s)|t = r|(s|t)        (rs)t = r(st)
r(s|t) = rs|rt            ∅|r = r                  ∅r = r∅ = ∅
εr = rε = r               r|r = r                  (r*)* = r*
∅* = ε                    ε* = ε                   (r*s*)* = (r|s)*

  1. Tentukan alphabet. "Simbol apa saja" ditulis (0|1) atau (a|b|c), dan "string apa saja" ditulis dengan star: (0|1)*.
  2. Cocokkan kalimat soal dengan salah satu pola di tabel.
  3. Uji dengan ε, string terpendek yang harus diterima, dan string yang hampir benar tetapi harus ditolak.

7. Regular definition

Regular definition adalah deretan definisi d₁ → r₁, d₂ → r₂, …. Setiap rᵢ boleh memakai nama yang didefinisikan sebelumnya. Hasilnya sama dengan satu RE panjang, tetapi lebih mudah dibaca.

letter       → A | B | … | Z | a | b | … | z
digit        → 0 | 1 | … | 9
id           → letter (letter | digit)*

digits       → digit digit*
opt-fraction → ( . digits )?
opt-exponent → ( E (+|-)? digits )?
unsigned-num → digits opt-fraction opt-exponent

unsigned-num cocok dengan 5280, 39.37, 6.336E4, dan 1.894E-4.

8. Latihan

Soal 1–5 adalah latihan di slide dosen. Coba tulis sendiri dulu, lalu uji di visualisasi.

1. String di atas {a, b, c} yang memuat minimal satu a dan satu b.

Jawaban

(a|b|c)*a(a|b|c)*b(a|b|c)* | (a|b|c)*b(a|b|c)*a(a|b|c)*

Butuh dua urutan, karena a boleh muncul sebelum atau sesudah b. Dengan satu urutan saja, ba ditolak.

2. String 0 dan 1 yang simbol ketiganya dari kanan adalah 1.

Jawaban

(0|1)*1(0|1)(0|1). Setelah angka 1 itu ada tepat dua simbol. Uji: 100 diterima, 0100 diterima, 010 ditolak, 11 ditolak (terlalu pendek).

3. String di atas {a, b} yang diawali abb.

Jawaban

abb(a|b)*

4. String di atas {0, 1} yang memuat substring 011.

Jawaban

(0|1)*011(0|1)*

5. String di atas {0, 1} yang diawali atau diakhiri (atau keduanya) dengan 01.

Jawaban

01(0|1)* | (0|1)*01. "Atau keduanya" tidak butuh bagian tambahan, karena string seperti 0101 sudah cocok dengan bagian kiri.

6. Language apa yang dihasilkan (0|1)*0(0|1)?

Jawaban

String yang simbol keduanya dari kanan adalah 0. String terpendek: 00, 01, 000, 001, 100, 101.

7. Kenapa a*b* tidak sama dengan (a|b)*? Beri satu string pembeda.

Jawaban

ba. Di a*b*, semua a harus muncul sebelum semua b, jadi ba ditolak. (a|b)* menerimanya.

8. Tulis RE untuk string 0 dan 1 yang tidak memuat 00.

Jawaban

(1|01)*(0|ε). Setiap 0 di tengah harus langsung diikuti 1, jadi bagian yang diulang adalah 1 atau 01. Di akhir boleh ada satu 0 tambahan. Uji: ε, 0, 010, 1101 diterima, 100 ditolak.
