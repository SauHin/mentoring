Tabel LL(1) dan trace parser

Parser LL(1) menjalankan predictive parsing tanpa rekursi: cukup stack dan satu tabel. Target: kamu bisa mengisi parsing table dari FIRST dan FOLLOW, menjalankan trace stack untuk sebuah string, menentukan apakah grammar LL(1), dan menjalankan panic-mode error recovery.

Parser LL(1) hanya butuh input, stack, dan parsing table

predictive parser (materi 10), stack (data structure) mengisi tabel (2️⃣), aksi parser (3️⃣)

Tabel ongkos kirim: baris kota asal, kolom kota tujuan, dan isinya tarif. Kamu tidak menghitung apa-apa, cukup melihat sel.

tabel ongkos kirim selalu terisi. Di parsing table, sel kosong berarti error.

LL(1) parser adalah predictive parser tanpa rekursi (table-driven): pilihan produksi dibaca dari parsing table M[A, a]. Namanya berarti: input dibaca dari Left ke kanan, menghasilkan Leftmost derivation, dengan 1 token lookahead.

BagianIsi
Input bufferstring yang di-parse, diakhiri $
Stacksimbol grammar. Awalnya $ di dasar dan start symbol di atasnya
Parsing table Mbaris = variabel, kolom = terminal dan $, sel = satu produksi atau kosong
Outputproduksi yang dipakai, berurutan

Stack di sini menggantikan rekursi di recursive predictive parsing: isinya adalah simbol yang masih harus dicocokkan dengan input, dari atas ke bawah.

LL(1) = stack + tabel. Parser tidak pernah menebak, hanya membaca sel.

Soal latihan: Kenapa stack awal berisi $ di bawah start symbol?

$ menandai dasar stack. Kalau top stack sudah $ dan input juga tinggal $, semua simbol sudah cocok, jadi parsing selesai.

Produksi A → α ditulis di kolom FIRST(α), dan kalau α bisa ε, di kolom FOLLOW(A)

FIRST dan FOLLOW, label case di procedure (materi 10) aksi parser (3️⃣), conflict (6️⃣)

Papan petunjuk di gerbang tol: kalau tujuanmu Bandung, ambil gerbang 3.

di tol, satu tujuan boleh punya dua gerbang yang sama-sama benar. Di parsing table, dua produksi di satu sel berarti grammar-nya bukan LL(1) (6️⃣).

Proses setiap produksi A → α satu per satu (aturan slide):

  1. Untuk setiap terminal a di FIRST(α): tulis A → α di M[A, a].
  2. Kalau ε ada di FIRST(α): tulis A → α di M[A, b] untuk setiap b di FOLLOW(A), termasuk $.
  3. Sel yang tetap kosong berarti error.

Contoh slide: S → aBa, B → bB | ε. FIRST(B) = {b, ε}, FOLLOW(B) = {a}.

B → ε punya FIRST(ε) = {ε}, jadi produksi ini pergi ke kolom FOLLOW(B) = {a}.

Setiap langkah melihat top stack X dan input a: pop kalau sama, ganti X dengan isi M[X, a] kalau variabel

bagian parser (1️⃣), parsing table (2️⃣) trace lengkap (4️⃣)

Daftar belanja yang dicoret dari atas. Kalau barang teratas ada di rak depanmu, ambil dan coret. Kalau tulisannya "bahan kue", ganti dengan rinciannya: tepung, telur, gula.

saat belanja, kamu bebas mengambil tidak urut. Parser harus mencocokkan tepat dari top stack.

M[B, a] = B → ε. Pop B dan tidak push apa-apa. Input tidak maju, jadi langkah berikutnya mencocokkan a di top dengan input a.

Produksi di kolom aksi, dibaca dari atas, adalah leftmost derivation dan bisa digambar menjadi parse tree

trace (4️⃣), LMD dan parse tree (materi 07) grammar yang bukan LL(1) (6️⃣)

Struk belanja: urutan barang di struk menunjukkan urutan kasir memindainya.

struk tidak menunjukkan barang mana masuk kantong mana. Pengelompokan itu baru terlihat di parse tree, jadi tree-nya perlu digambar.

Variabel di top stack selalu variabel paling kiri yang belum diganti. Jadi urutan produksi di output sama dengan urutan leftmost derivation (materi 07). Contoh slide, trace abba di 3️⃣:

Output: S → aBa,  B → bB,  B → bB,  B → ε

S ⇒ aBa ⇒ abBa ⇒ abbBa ⇒ abba

Output LL(1) = LMD, karena variabel paling kiri selalu ada di top stack.

Kalau satu sel berisi dua produksi, grammar-nya bukan LL(1)

mengisi tabel (2️⃣), left factoring dan left recursion (materi 08, 09) syarat LL(1) tanpa tabel (7️⃣)

Papan petunjuk dengan dua panah untuk tujuan yang sama.

di jalan kamu bebas memilih salah satu. Parser LL(1) tidak boleh menebak, karena menebak berarti kembali ke backtracking.

LL(1) grammar adalah grammar yang parsing table-nya tidak punya sel berisi lebih dari satu produksi. Sel seperti itu disebut conflict. Contoh slide:

S → iCtSE | a        FIRST(S) = {a, i}   FOLLOW(S) = {e, $}
E → eS | ε           FIRST(E) = {e, ε}   FOLLOW(E) = {e, $}
C → b                FIRST(C) = {b}      FOLLOW(C) = {t}
Mabeit$
SS → aS → iCtSE
EE → eS
E → ε		E → ε
CC → b

e ada di FIRST(eS) dan juga di FOLLOW(E), jadi M[E, e] berisi dua produksi. Kalau i = if, t = then, e = else, ini masalah dangling else: else bisa milik if yang mana pun, jadi grammar-nya ambiguous.

Kalau tabel punya conflict (slide):

  1. Hapus left recursion kalau belum (materi 09).
  2. Lakukan left factoring kalau belum (materi 08).
  3. Masih ada conflict: grammar ambiguous atau memang bukan LL(1). Pakai parser lain, misalnya bottom-up.

Satu sel, dua produksi = bukan LL(1). Coba perbaiki grammar dulu.

Soal latihan: Apakah S → aS | a LL(1)? Kalau tidak, perbaiki.

Bukan. FIRST(aS) = FIRST(a) = {a}, jadi M[S, a] berisi dua produksi. Left factoring: S → aS', S' → S | ε. Sekarang FIRST(S) = {a} dan FOLLOW(S') = {$}, jadi M[S', a] = S' → S dan M[S', $] = S' → ε. Tidak ada conflict, jadi LL(1).

Tanpa membuat tabel: grammar left recursive, belum di-left factoring, atau ambiguous pasti bukan LL(1)

conflict (6️⃣) soal "apakah grammar ini LL(1)?"

Pemeriksaan di pintu ruang ujian: tanpa kartu ujian, kamu pasti ditolak, jadi petugas tidak perlu memeriksa yang lain.

membawa kartu ujian belum menjamin kamu boleh masuk. Grammar tanpa tiga tanda ini juga belum tentu LL(1), jadi tetap cek syarat di bawah.

Tanda (slide)Kenapa pasti ada conflict
Left recursive: A → Aα | βAα ⇒ βα, jadi terminal di FIRST(β) juga ada di FIRST(Aα)
Belum left factoring: A → αβ₁ | αβ₂kedua alternatif memuat terminal pertama dari α
Ambiguoussatu string punya dua parse tree, jadi di suatu titik ada dua pilihan

Syarat lengkapnya: grammar LL(1) kalau dan hanya kalau untuk setiap dua produksi A → α | β:

  1. FIRST(α) dan FIRST(β) tidak beririsan: keduanya tidak bisa diawali terminal yang sama.
  2. Paling banyak satu yang nullable: α dan β tidak boleh sama-sama bisa menjadi ε.
  3. Kalau β nullable: FIRST(α) tidak beririsan dengan FOLLOW(A).

Template jawaban: "Grammar ini bukan LL(1), karena untuk A → α | β, terminal a ada di FIRST(α) dan di [FIRST(β) / FOLLOW(A)]." Atau: "Grammar ini LL(1), karena setiap sel parsing table berisi paling banyak satu produksi."

Tiga tanda bahaya: left recursive, belum left factoring, ambiguous. Kalau tidak ada, cek tiga syarat.

Soal latihan: Mana yang LL(1)? (a) E → E+T | T, (b) A → aB | aC, (c) S → aSb | ε.
  • (a) Bukan: left recursive.
  • (b) Bukan: belum left factoring, kedua alternatif diawali a.
  • (c) LL(1): FIRST(aSb) = {a}, FOLLOW(S) = {b, $}. Hanya ε yang nullable, dan {a} tidak beririsan dengan {b, $}.

Panic mode: buang input sampai ketemu simbol di FOLLOW(A), lalu pop A, supaya parser bisa mencari error berikutnya

error di trace (4️⃣), FOLLOW (materi 10) compiler yang melaporkan banyak error sekaligus

Membaca teks yang sebagian tercoret: lompati sampai awal kalimat berikutnya (setelah titik), lalu lanjut membaca.

titik di teks selalu jelas. Parser menebak "awal berikutnya" dari FOLLOW, jadi kadang ada input yang terbuang bersama error lain di dalamnya.

Panic mode adalah error recovery yang membuang token input sampai ketemu synchronizing token, lalu melanjutkan parsing. Untuk variabel A, synchronizing token-nya adalah terminal di FOLLOW(A). Cara sederhana dari slide:

  • Sel kosong M[A, a] (ditandai sync): buang input sampai token sekarang ada di FOLLOW(A) (atau $), lalu pop A.
  • Terminal di top ≠ input: pop terminal itu, dan laporkan "missing …, inserted".

Contoh slide: S → AbS | e | ε, A → a | cAd, FOLLOW(A) = {b, d}. Input ceadb:

Soal latihan: Dengan grammar yang sama, top stack A dan input eb$. Apa yang dilakukan panic mode?

M[A, e] kosong (sync). Buang e, karena e tidak ada di FOLLOW(A) = {b, d}. Sekarang input b ada di FOLLOW(A), jadi berhenti membuang dan pop A.

Kesalahan yang sering muncul: kolom ε, push tidak dibalik, dan accept terlalu cepat

semua section sebelumnya soal ujian: tabel, trace, dan cek LL(1)

Menyusun piring di rak: piring yang ingin kamu ambil pertama harus diletakkan terakhir.

piring yang tertukar masih bisa dipakai. Simbol yang di-push terbalik membuat parser mencocokkan urutan yang salah, dan string yang valid ditolak.

Setelah trace selesai, cek baris terakhirnya: string accepted hanya kalau stack tinggal $ dan input juga tinggal $.
